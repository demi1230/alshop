# AlShop Deployment Guide - Railway

Complete step-by-step guide for deploying AlShop to Railway.app.

## 📋 Prerequisites

Before deploying, ensure you have:

1. **GitHub Account** - Railway integrates with GitHub
2. **Railway Account** - Sign up at [railway.app](https://railway.app)
3. **Rails Master Key** - Located at `config/master.key`
4. **Git Repository** - Code pushed to GitHub
5. **Basic Knowledge** - Understanding of Docker and environment variables

## 🚀 Quick Start (5 minutes)

### 1. Create Railway Project

```bash
# Navigate to your project directory
cd ~/alshop

# Install Railway CLI (optional but helpful)
npm install -g @railway/cli

# Login to Railway
railway login
```

### 2. Connect GitHub Repository

1. Go to [railway.app](https://railway.app)
2. Click **"New Project"**
3. Select **"GitHub Repo"**
4. Authorize Railway to access GitHub
5. Select the `alshop` repository
6. Railway will auto-detect Rails application

### 3. Set Environment Variables

In Railway Dashboard:

1. Go to **Project Settings → Variables**
2. Add the following variables:

| Variable | Value |
|----------|-------|
| `RAILS_ENV` | `production` |
| `RAILS_MASTER_KEY` | (copy from `config/master.key`) |
| `DATABASE_URL` | (auto-generated by Railway) |
| `RAILS_LOG_TO_STDOUT` | `true` |

### 4. Deploy

```bash
# Push to main branch to trigger deployment
git add .
git commit -m "Ready for deployment"
git push origin main
```

Railway automatically:
- Builds Docker image
- Runs migrations
- Seeds database (if configured)
- Starts application

✅ **Your app is now live!**

## 📝 Detailed Setup Guide

### Step 1: Prepare Your Code

#### 1a. Ensure Git is Clean

```bash
cd ~/alshop
git status

# Should show nothing or only untracked files
git add .
git commit -m "Pre-deployment commit"
```

#### 1b. Verify Dockerfile

The Dockerfile at root of project handles:
- Ruby version (3.4.8)
- Dependency installation
- Asset precompilation
- Puma server startup

**No changes needed** - Dockerfile is pre-configured for Railway.

#### 1c. Check Procfile

`Procfile` (not `Procfile.dev`) should exist:

```
web: ./bin/thrust ./bin/rails server
```

If missing, create it:

```bash
echo "web: ./bin/thrust ./bin/rails server" > Procfile
```

### Step 2: Configure Railway Account

#### 2a. Sign Up

1. Go to [railway.app](https://railway.app)
2. Click **"Start Free"**
3. Sign up with GitHub (recommended for easier integration)
4. Authorize Railway to access your GitHub account

#### 2b. Create New Project

1. Click **"New Project"** button
2. Select **"Deploy from GitHub"**
3. Find and select `alshop` repository
4. Click **"Deploy"**

Railway will:
- Create project
- Detect Rails application
- Create PostgreSQL database (optional)
- Show deployment logs

### Step 3: Set Environment Variables

#### 3a. Get RAILS_MASTER_KEY

```bash
cat config/master.key
```

Copy the output (64-character string).

#### 3b. In Railway Dashboard

1. Click on your project
2. Go to **Settings → Variables**
3. Add environment variables:

```
RAILS_ENV=production
RAILS_MASTER_KEY=<paste from config/master.key>
RAILS_LOG_TO_STDOUT=true
```

#### 3c. Database Configuration

**Option A: Use Railway's PostgreSQL (Recommended)**

1. In Railway Dashboard, add **"Add Service"**
2. Select **"PostgreSQL"**
3. Railway auto-configures `DATABASE_URL`

**Option B: Keep SQLite (Simpler)**

1. No additional setup needed
2. Database persists in `/app/storage/`
3. May be slower for large datasets

### Step 4: Configure Dockerfile (if needed)

If Railway doesn't auto-detect, create/verify Dockerfile:

```dockerfile
# Dockerfile
FROM ruby:3.4.8-slim

WORKDIR /app

# Install system dependencies
RUN apt-get update && apt-get install -y \
    build-essential \
    sqlite3 \
    postgresql-client \
    && rm -rf /var/lib/apt/lists/*

# Copy files
COPY Gemfile Gemfile.lock ./
RUN bundle install

COPY . .

# Precompile assets
RUN RAILS_ENV=production SECRET_KEY_BASE=dummy bundle exec rails assets:precompile

# Run migrations
RUN RAILS_ENV=production bundle exec rails db:migrate

EXPOSE 3000

CMD ["bundle", "exec", "rails", "server", "-b", "0.0.0.0", "-p", "3000"]
```

### Step 5: Deploy

#### 5a. First Deployment (Manual)

```bash
# Ensure all changes are committed
git status

# If untracked files exist, add them
git add .
git commit -m "Ready for Railway deployment"

# Push to main (or your deploy branch)
git push origin main
```

Railway automatically:
1. Detects code changes
2. Builds Docker image
3. Runs migrations
4. Starts application
5. Exposes on public URL

#### 5b. View Deployment Logs

1. Go to Railway Dashboard
2. Click **"Deployments"** tab
3. Click latest deployment
4. View real-time logs

**Common issues:**
- `RAILS_MASTER_KEY not set` → Add to variables
- `Database connection failed` → Check DATABASE_URL
- `Asset compilation failed` → Check Gemfile for syntax errors

### Step 6: Verify Deployment

Once deployment completes:

```bash
# Check deployment status
railway status

# Open application in browser
railway open

# Tail logs
railway logs -f
```

Or manually:

1. Go to Railway Dashboard
2. Click project
3. Copy domain URL from **"Domains"** section
4. Visit `https://your-app.railway.app`

**Expected output:** AlShop homepage with products listing

## 🔧 Post-Deployment Configuration

### Database Setup

#### First-Time Setup

```bash
# SSH into Railway container
railway shell

# Inside container, run migrations
bundle exec rails db:migrate

# Seed database with example data
bundle exec rails db:seed

# Exit container
exit
```

#### Verify Database

```bash
railway shell

# Check database connectivity
bundle exec rails dbconsole

# Exit dbconsole
.quit
```

### Admin User Setup

Create admin user for accessing `/admin` panel:

```bash
railway shell

# Inside container
bundle exec rails console

# Create admin user
User.create!(
  email: 'admin@alshop.com',
  password: 'SecurePassword123!',
  password_confirmation: 'SecurePassword123!',
  role: 'admin'
)

# Verify
User.find_by(email: 'admin@alshop.com').role
# => 'admin'

exit
```

### Verify Admin Access

1. Go to your app URL: `https://your-app.railway.app`
2. Click **"Sign In"** (top right)
3. Use admin credentials
4. Should see **"Admin Panel"** link
5. Click to access `/admin/dashboard`

## 🔒 Security Configuration

### 1. HTTPS/SSL

Railway automatically provides SSL certificates. All traffic is encrypted.

**Verify:**
```bash
# Visit your app
curl -I https://your-app.railway.app
# Should show: HTTP/2 200
```

### 2. Environment Variables

**Never commit secrets to Git:**

```bash
# ❌ Never do this
git add config/master.key
git commit -m "Add master key"

# ✅ Always use Railway environment variables
RAILS_MASTER_KEY=xxx (in Railway dashboard)
```

### 3. Database Security

**With Railway PostgreSQL:**
- Credentials automatically managed
- No manual password handling
- Encrypted connections

**With SQLite:**
- Single-file database
- Less secure for production
- Recommend PostgreSQL for production

### 4. IP Whitelisting (Enterprise)

Coming soon in Railway. For now, rely on:
- Strong user passwords
- HTTPS encryption
- Input validation

## 🆘 Troubleshooting

### Deployment Fails: "RAILS_MASTER_KEY not set"

**Solution:**
1. Go to Railway Dashboard
2. Click **Settings → Variables**
3. Add: `RAILS_MASTER_KEY=<value from config/master.key>`
4. Redeploy

```bash
git commit --allow-empty -m "Trigger redeploy"
git push origin main
```

### Application Crashes: "Database connection failed"

**Solution:**
1. Verify DATABASE_URL variable exists
2. If using PostgreSQL, ensure service is running
3. Check migrations ran successfully:

```bash
railway shell
bundle exec rails db:migrate
exit
```

### Slow Application / Timeouts

**Solutions:**
1. Increase container memory in Railway Settings
2. Check for N+1 queries:
   ```ruby
   # Bad - N+1 queries
   Product.all.each { |p| p.category.name }
   
   # Good - eager loading
   Product.includes(:category).all
   ```
3. Enable caching in `config/environments/production.rb`

### Migrations Fail on Deploy

**Check logs:**
```bash
railway logs -f
```

**Common causes:**
- Invalid migration syntax
- Missing schema file
- Database locked

**Fix:**
```bash
railway shell
bundle exec rails db:rollback
bundle exec rails db:migrate
exit
```

### Assets Not Loading (404 errors)

**Solution:**
1. Force asset recompilation:
   ```bash
   RAILS_ENV=production bundle exec rails assets:precompile
   ```
2. Clear Rails cache:
   ```bash
   bundle exec rails cache:clear
   ```
3. Redeploy

### Image/File Upload Not Working

**With SQLite:**
- Files stored in `/app/storage`
- Persists between deployments

**With separate storage:**
1. Add AWS S3 configuration
2. Set environment variables in Railway
3. Files upload to cloud storage

## 📦 Database Backup

### Export Database

**From SQLite:**
```bash
railway shell

# Inside container
cd storage
sqlite3 development.sqlite3 ".dump" > backup.sql

# Exit and copy locally
exit

railway download storage/backup.sql
```

**From PostgreSQL:**
```bash
railway shell

# Inside container
pg_dump $DATABASE_URL > backup.sql

exit

railway download backup.sql
```

### Import Database

```bash
# Upload backup file
railway upload backup.sql

railway shell

# Inside container
sqlite3 development.sqlite3 < backup.sql

exit
```

## 🌐 Custom Domain

### Configure Custom Domain

1. Go to Railway Dashboard
2. Click **Settings → Domains**
3. Add domain: `alshop.yourdomain.com`
4. Update DNS records (shown in Railway):
   ```
   CNAME: your-app.railway.app
   ```
5. Wait for DNS propagation (1-24 hours)

### SSL Certificate

Railway automatically provisions SSL for custom domains via Let's Encrypt.
